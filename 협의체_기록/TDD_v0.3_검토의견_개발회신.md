## 1. 수용 불가 또는 검토서 정정 필요

### (1) 등급표의 "유효한 시크릿 하드코딩" — 원칙 충돌로 문구 수용 불가 🔴

시크릿 유효성 검증은 검출된 키를 실제 서비스에 호출해야 확인되며, TDD §4.2는 "TruffleHog식 실검증은 시크릿 외부 전송이라 원칙상 배제"로 확정되어 있다. 위험 기준을 **"시크릿 패턴 confirmed 검출(gitleaks regex+entropy 기준)"**로 재정의 제안. 2축 등급 구조 자체는 전면 수용(현행 기준의 '위험' 수렴 지적이 정확).

### (2) §2-7 재구성안은 9종이 아니라 10종 🔴

제시된 표는 P1~P10 10종(9−1+2=10)으로 "총수 9종 유지·기획서 수정 불필요" 주장과 모순.

- **A안(권장)**: 10종 확정 + 기획서 "9종"→"10종" 한 곳 수정
- B안: P7+P8을 §7.3.4 안전조치 룰 하나로 통합해 9종 유지(룰별 검출률 표가 흐려지는 단점)

신규 P5(크롤링)·P9(처리방침 공개) 채택 자체는 동의. **부수 정정**: MVP 포기 후보 "P4·P5"는 순수 LLM 룰인 **P1·P4**로 갱신 필요(신규 P5는 static+LLM이라 기존 제외 사유가 적용되지 않음).

### (3) 제3자 벤치마크 앱으로 DVWA는 부적합 ⚠️

DVWA는 PHP — 진단 대상 언어(Python, JS/TS) 밖. 대상은 **OWASP Juice Shop(Node/TS)** 또는 **PyGoat(Python/Django)**. 검출률 측정은 해당 앱의 공식 문서화된 취약점 목록에 한정.

### (4) 라이선스 결합형태 3분류 — 축별 비용 차이가 큼 ⚠️

- 미수정 라이브러리 참조(동적): 매니페스트 판정 — MVP 포함 ✅
- 파일단위 복제(vendored): 휴리스틱 best-effort ⚠️
- 수정 후 사용: 원본 릴리즈 다운로드·해시 대조 필요 — **V2 또는 일정 여유 시** ❌

SBOM ⑨ 필드에 3분류 체계는 도입하되 판정 수준을 위와 같이 단계화해 문서에 명시.

### (5) §3-3 집계 공개 — 기본 V2 + 발표 로드맵 언급

M6에 소유 증명·재진단 분기 등이 이미 추가되어, M6 조기 완료 시에만 최소 구현(진단 수·등급 분포 1화면)하는 스트레치 골로 분류.

## 2. 조건부 수용

### §1-2 소유권 검증 — zip 공개 제외까지 포함해 수용

지문은 동일성 증명이지 권한 증명이 아니라는 지적이 정확. 개발 측 추가 논거: **git 경로에 소유 증명을 넣어도 zip 공개를 열어 두면 우회로가 된다**(타인의 공개 저장소를 zip으로 받아 올리면 됨). 소유 증명과 zip 공개 제한은 세트여야 유효.

- ADR-001 v1.2의 "zip 공개 허용"은 번복, **v1.3 개정** 제안
- git: 발급 토큰 `.ansimcode` 파일 커밋 확인 → 공개 슬러그 발급 (M6, 약 반나절)
- zip: 공개 페이지·배지 대상 제외, 본인 세션 열람만
- 일정 폴백: 고지 문구 + §11 등재

### §2-2 조항 오귀속(§9.3→§9.5) — 수용, 반영 직전 원문 재확인 1회

표준 PDF 보유처(기획)와 §9.5 해당 문단을 함께 확인 후 TDD·기획서 동시 반영.

### §6-5 일정(목표 8/30) — 수용 전제: 개정 MVP 포기 순서의 기획 승인

이번 검토는 일정을 하루 줄이면서 구현 범위를 순증시켰다. §4의 개정 포기 순서를 기획이 승인하면, 압박 시 그 순서대로 사후 협의 없이 자른다.

## 4. MVP 포기 순서 개정안

> ① §7.1~7.2 체크리스트 화면(정적 페이지) → ② SVG 배지(고정 이미지) → ③ 집계 통계(V2/스트레치) → ④ 소유 증명(고지 문구로 대체) → ⑤ 재진단 diff 화면(등급 변화만 표시로 축소, 재진단 자체는 유지) → ⑥ P1·P4(데모 제외) → ⑦ 공급망 분류(최후순위)

공급망 분류는 "처음부터 단순 구현" 지적 수용. 재진단은 기능 자체를 포기하지 않음(표준 3종 근거 동시 상실 지적 동의).
