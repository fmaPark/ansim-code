## 1. 확정 사항 기록 (개발이 이해한 결정 — 어긋나면 정정 요청)

1. LLM 공급자를 Anthropic Claude → **Google Gemini로 전면 교체**한다(비용 절감 목적).
2. **Anthropic 경로는 코드에 남기지 않는다.** transport·설정·의존성(`anthropic` 패키지)을 제거하며, 복구 수단은 git 이력뿐이다. `ANTHROPIC_API_KEY`는 `.env`·`.env.example`에서 폐기한다.
3. 수행 시점은 데모 전(08-30 당일)이며, 당일 검증 게이트(§3) 미충족 시 LLM 단계를 데모에서 제외한다.

## 3. 전면 교체 확정으로 달라진 리스크 — 검토 시 유의점

이전 결정 요청 문서에서 A안(이원화)이 갖던 "게이트 실패 시 Anthropic 회귀" 안전판이 **이번 확정으로 제거**되었다. 그 결과:

- **당일 게이트 4건이 데모 성립 조건이 된다**: ① 벤치마크 페이로드(시크릿·주민번호·인젝션) 안전 필터 차단 0건 ② `model_version` 기록 확인(G9) ③ Gemini 리허설 캐시 재기록 ④ judge 12 병렬 쿼터 통과.
- 게이트 실패 시 폴백은 **"LLM 단계 데모 제외" 하나뿐**이다. 이 경우에도 스캔은 완주한다 — 검출(P1~P5·P10 포함, 정적 합성 초안 유지)·등급·리포트·재진단 전부 동작하고 시민용 설명·수정 프롬프트는 규칙 기반 폴백 문구로 채워진다. 잃는 것은 judge 판정 설명, LLM 생성 문구 품질, 그리고 **"제품 내장 AI" 서사와 인젝션 방어 시연(M7)**이다.
- 단, 현행 TDD §7 MVP 경계선은 "LLM 실호출 1개 이상 시나리오"를 **목업 불가**로 명시한다. 제외를 실행하려면 이 조항의 개정(기획 승인)이 선행되어야 한다 — 조용히 뺄 수 있는 항목이 아니다.

## 4. 잔여 확인 요청 (당일 회신 요청)

1. **§2 반영 내역의 완결성 확인** — 확정 사항과 어긋나거나 누락된 절이 있으면 지적 요청.
2. **모델 가정 승인**: judge=`gemini-2.5-flash`, 변환=`gemini-2.5-flash-lite`(비용 절감 목적에 맞춘 개발 가정). 상위 모델 지정 시 절감 폭이 줄어드는 점 참고.
3. **게이트 미충족 시 처리의 사전 승인**: 회귀 경로가 없으므로 실패 = LLM 데모 제외 + §7 MVP 경계선 개정이다. 실패가 데모 직전 판명될 수 있어 **지금 사전 승인**을 요청한다.

부수 선행 조건: `GEMINI_API_KEY` 발급·전달(미전달 시 게이트 실측 자체가 시작 불가).
