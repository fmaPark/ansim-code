## 각 문서의 내용

### TTAK.KO-11.0259/R1 — 오픈소스 소프트웨어 보안취약점 관리 지침

오픈소스 소프트웨어를 개발·사용할 때 보안취약점을 조기에 발견하고 위협을 제거하기 위한 절차와 관리 요소를 규정한다. 오픈소스 취약점의 특징 4가지(공개된 환경, 공개적 노출, Pull 지원 모델, 다양한 유입 경로)와 SDLC 단계별(요구사항 분석 → 설계 → 구현 → 테스트 → 유지보수) 점검 사항을 제시하고, OSRB를 중심으로 한 조직 구성과 환경분석 → 현황진단 → 위험분석 → 대책수립 → 이행관리의 5단계 관리 프로세스를 규정한다.

### TTAK.KO-11.0309/R1 — SBOM 속성 규격

SBOM에 포함해야 할 15가지 표준 속성(검증 도구, 공급자, 저작권자, 컴포넌트 이름·버전, 고유식별자, 해시, 라이선스 명·결합형태, 취약점 DB, 관계성, 릴리즈 날짜, CVE ID, CVSS Base Score, CVSS Severity)을 정의한다. SPDX·SWID·CyclonDX(원문 표기)가 라이선스나 보안취약점 어느 한쪽에 치우쳐 있다는 한계를 지적하고, 두 위험을 함께 관리할 기본 속성 집합을 제시한다.

### TTAK.KO-11.0322 — 오픈소스 SBOM 거버넌스 관리 지침

조직이 SBOM을 생성·유지·관리하기 위한 내부 관리체계 구축 지침이다. 공급망 환경과 비즈니스 모델 분석으로 위험요인과 SBOM 관리영역을 도출하는 거버넌스 프로세스, 정적분석·종속성 분석·컨테이너 분석 등 SBOM 생성도구, 라이선스 관리정책(Permissive / Weak·Strong Copyleft), 4개 주체별 역할과 기획–구현–검증–제품화 4단계 관리 프로세스를 다룬다. 속성 정의는 TTAK.KO-11.0309를 따른다.

### TTAK.KO-12.0414 — AI 서비스 개인정보보호 프레임워크

AI 서비스의 개인정보보호 원칙과 요구사항을 제시한다. AI 시스템 생명주기와 6가지 개인정보 공격유형(멤버십 추론, 모델 추출, 역모델, 속성 추론, 데이터 오염, 회피 공격), AI 신뢰성 구현 요구사항, 그리고 개인정보보호 6대 원칙(적법성·안정성·투명성·참여성·책임성·공평성)에 기반한 수집·이용제공·보관·파기 단계별 보호조치를 규정한다.

### 소프트웨어 개발보안 가이드(2021) — 행정안전부·한국인터넷진흥원

「행정기관 및 공공기관 정보시스템 구축·운영 지침」(행정안전부고시 제2021-3호)이 요구하는 **설계단계 보안설계 기준 20개 항목(SR1-1 ~ SR4-1)**과 **구현단계 보안약점 제거 기준 49개 항목**의 원문 기준이다. 설계단계 항목별로 취약점 개요·설계 시 고려사항·연관 구현단계 보안약점·사고사례를, 구현단계 49개 보안약점별로 개요·보안대책·JAVA/C/C#/Android 코드예제(안전하지 않은 코드 ↔ 안전한 코드)를 제공한다. 부록에는 보안설계 기준 원문, 보안약점 제거 기준 정의, 적용계획서·산출물 예시, 용어정리가 들어 있다.

원본이 376쪽이라 장 단위로 파일을 나누어 하위 디렉토리에 두었다. 구성과 전체 목차는 [소프트웨어 개발보안 가이드(2021) 색인](sw-dev-security-guide-2021/index.md)을 참고한다.

- 원본 PDF는 저장소에 포함하지 않는다. 각 문서 상단 인용 블록에 원본 파일명을 적어 두었다.
- 페이지 머리글·바닥글과 목차의 페이지 번호는 제거했고, 그 밖의 원문 내용은 그대로 옮겼다.
- 원문의 그림은 `**[그림 N] 캡션**` 형태로 표기하고 구성요소와 흐름을 텍스트로 풀어 썼다.
- 표는 마크다운 표로 옮겼다. 셀 병합이 있는 표는 구조를 근사해 표현했다.
- 코드예제가 있는 문서는 언어별 코드 블록으로 옮겼다.
