# AI 활용 정리 — 안심코드(AnsimCode)

근거는 `logs/agent/` 세션 백업 23건(2026-08-24 ~ 08-31)과 GitHub의 PR·이슈·커밋이다.
제품이 내부적으로 LLM을 쓰는 부분은 [tdd.md](tdd.md) §4.2가 정본이고, 여기서는 3장에서만 다룬다.

---

## 요약

안심코드는 **기획자 1명 + 개발자 1명이 8일 만에** 만든 데모다.
설계·코드·문서·PR 본문·팀 메시지 초안까지 사실상 전부 AI가 생산했고,
사람은 **무엇을 사실로 볼지, 무엇을 자를지, 무엇을 승인할지**를 결정했다.

핵심은 "AI에게 매번 설명하지 않는다"였다. **설계 → 계획 → 프롬프트 → 실행**을 4단계 문서 체인으로 만들고,
각 단계 산출물을 저장소에 고정해 다음 단계가 그걸 읽게 했다. 프롬프트조차 대화에 흘리지 않고
[실행 프롬프트 문서](plans/execution-prompts.md)로 버전 관리했다.

| 지표 | 값 |
| --- | --- |
| 기간 | 2026-08-24 ~ 08-31 (8일) |
| 세션 | **23건** — 로컬 워크트리 13 · 저장소 루트 7 · Cowork(Windows, 팀원) 2 · claude.ai 웹 1 |
| 사람이 입력한 프롬프트 | **161개** |
| 커밋 | 123건 중 **76건에 AI 공동저자 표기** (Fable 5 43 · Opus 5 29 · Opus 4.8 4) |
| PR / 이슈 | 27건 / 14건 — 본문 전량 AI 작성 |
| 사람이 직접 쓴 코드 | 사실상 없음 |

**이 프로젝트 AI 활용의 특징 5가지**

1. **프롬프트를 문서로 관리했다.** 세션별 프롬프트를 저장소 산출물로 만들어 리뷰·수정·재사용했다. 같은 프롬프트로 다시 돌리면 같은 절차가 재현된다.
2. **프롬프트만 전담하는 세션을 따로 뒀다.** 코드를 한 줄도 건드리지 않고 스킬 조사와 프롬프트 작성만 하는 세션이 이틀간 살아 있었다.
3. **지켜야 할 규칙을 프롬프트가 아니라 문서에 고정했다.** 16개 제약(G1~G16)과 최우선 3건(P0)을 표로 두고 프롬프트는 참조만 한다.
4. **AI에게 자기 채점을 시키지 않았다.** 정답지(벤치마크 취약점 목록)를 룰 구현보다 **먼저** 확정하고, 기획자의 GitHub 리뷰 승인을 통과 조건으로 걸었다.
5. **완성된 제품으로 자기 자신을 진단했다.** AI가 만든 스캐너로 AI가 쓴 코드를 검사해 오탐 3종을 찾아 이슈로 등록했다.

## 1. 전체 워크플로우

### 1.1 문서 4단 체인

```
제안서(PDF) ─▶ tdd.md · platform-decision.md ─▶ plans/mvp-implementation.md ─▶ plans/execution-prompts.md ─▶ 구현 세션 6개
                    설계 문서                        28개 태스크 계획              세션별 프롬프트                     실행
```

단계마다 산출물이 다음 단계의 입력이 된다. 계획 문서에는 태스크마다 **TDD 섹션 번호**를 적어 뒀다 —
구현 세션이 설계 문서를 다시 읽지 않아도 되게 하기 위해서다.

가장 특징적인 건 3~4단계 사이다. 보통 프롬프트는 대화창에서 한 번 쓰고 사라지는데,
여기서는 [plans/execution-prompts.md](plans/execution-prompts.md)라는 **문서로 만들어 PR로 리뷰받았다**(PR #5).
세션 S1~S6의 프롬프트 전문과 병렬 실행용 변형 3종이 들어 있고, 각각 복사-붙여넣기만으로 단독 동작한다.
나중에 벤치마크 명세가 확정되자 이 문서의 S6 프롬프트를 갱신했다(PR #25).

### 1.2 프롬프트 전담 세션 — "프롬프트 발사대"

파일을 **하나도 수정하지 않는** 세션 하나가 8/29 새벽부터 8/31 새벽까지 살아 있었다.
하는 일은 두 가지뿐이다.

* **스킬 조사** — `/find-skills`로 "설계문서 기반 구현", "테스트 시나리오" 같은 키워드를 검색해 후보를 비교하고 설치. `executing-plans`·`writing-plans`·`agents-md`·`test-driven-development`·`verification-before-completion`이 여기서 들어왔다.
* **프롬프트 생산** — "다른 세션에서 진행할 거라 프롬프트 작성", "다른 세션에서 쓸 프롬프트로 정리해줘"가 반복된다. 구현·AGENTS.md·README·전체 테스트 프롬프트가 이 세션에서 나왔다.

프롬프트를 다듬는 방식도 여기서 드러난다. 전체 테스트 프롬프트에는 나중에
"이슈를 critical/high/medium/low로 구분하고 **기준도 정해 줘**, 발견한 이슈는 GitHub 이슈로 등록하고
priority를 태그로, high 이상은 담당자 지정"이 추가됐다. **판정 기준과 후속 처리까지 프롬프트에 넣는** 방식이다.

### 1.3 한 세션 = 한 마일스톤 = 한 브랜치 = 한 PR

구현 프롬프트 6개가 전부 같은 문장으로 시작한다.

> 이번 세션 범위: Task N~M만. **범위 밖 태스크는 절대 건드리지 말 것.**
> 브랜치: (직전 마일스톤이 병합된 최신 베이스)에서 분기. **main 직접 작업 금지.**

23건 중 13건은 워크트리(같은 저장소의 격리된 사본)에서 돌렸다. 덕분에 M2·M3와 M4를 **동시에** 진행할 수 있었고,
충돌이 예상되는 파일 2개를 프롬프트에 미리 적어 병합 비용을 예측 가능하게 만들었다.
로그를 시각순으로 보면 8/29 새벽에 4개, 8/30 오후에 3개 세션이 같은 시간대에 열려 있다.

### 1.4 규칙은 프롬프트가 아니라 문서에

프롬프트가 길어지면 지시가 흐려진다. 그래서 불변 규칙 16개(G1~G16)를 계획 문서에 표로 고정하고,
프롬프트는 "G1~G16을 그대로 따를 것"으로 참조만 한다. 그중 **P0 3건**은 어떤 판단보다 우선한다.

| | 규칙 | 왜 |
| --- | --- | --- |
| G1 | 원본 코드는 격리 공간에만 두고 **어떤 실패 경로에서도 삭제** | 에이전트가 편의상 남겨두는 경로 차단 |
| G2 | 시크릿 원문은 DB·로그·리포트 어디에도 금지, LLM 전송 직전 마스킹 | 제품의 AI에게 비밀을 보내지 않는다 |
| G3 | 등급은 정적 분석 결과만의 함수. **LLM 판단은 등급에 못 들어간다** | 제품의 AI가 결과를 흔들지 못하게 |

태스크마다 완료 조건(DoD)과 마일스톤 게이트를 붙여, 세션이 스스로 "끝났다"고 선언하지 못하게 했다.
게이트는 **실제 명령을 돌린 출력**으로만 통과된다.

### 1.5 모델은 고정 규칙, 결과는 커밋에 표기

기준은 하나다 — **계획 단계는 Fable 5, 구현 단계는 Opus 5.** 세션마다 판단한 게 아니라 고정 규칙이었고,
사람은 모델이 잘못 지정돼 있을 때만 수동으로 되돌렸다(로그상 7회).

커밋에는 **실제로 그 커밋을 만든 모델**을 공동저자로 적는 규약을 뒀다(`AGENTS.md`).
그래서 "Fable 5 43건 / Opus 5 29건 / Opus 4.8 4건"이 추정이 아니라 커밋 단위 실측이다.

### 1.6 세션 기록을 자동화하고, 저장소를 AI가 읽는 형태로 정비

* **첫 세션의 주제가 "세션 백업 스킬 만들기"였다.** 대화 전문·도구 호출·변경 파일 목록을 마크다운으로 떨어뜨리는 스킬을 직접 만들어 18회 썼다. 이 문서의 근거 자체가 그 산출물이다.
* **`AGENTS.md`** — 에이전트용 저장소 지침. 설계 내용은 복제하지 않고 포인터만 둔다(설계 문서를 요약해 옮기면 곧 실제와 어긋나므로).
* **`docs/`를 지식 번들로 전환** — 모든 문서에 메타데이터·목차·변경 이력·검사 스크립트를 붙여, AI가 안정적으로 탐색·인용할 수 있게 했다.
* **표준 원문을 마크다운으로 변환** — TTA 표준 4종 + 개발보안 가이드 376쪽. 이후 모든 세션이 PDF 재파싱 없이 조항을 인용한다.

### 1.7 이슈 트래커가 다음 세션의 입력

세션 완료 보고의 '보류·이월 항목'이 그대로 GitHub 이슈가 되고, 다음 세션 프롬프트가 된다.

```
세션 보고(이월) ─▶ 이슈 등록 ─▶ 다음 세션 프롬프트("이슈 #13, #15 픽스") ─▶ PR ─▶ 머지·이슈 닫기
```

이슈 #16은 아예 **게이트**로 등록됐다 — "벤치마크 취약점 목록 기획 확정, M7 착수 전 마감".

### 구현 세션 6건의 공통 틀

```
범위 제한 → 브랜치 지정 → G1~G16·완료조건 준수
→ 테스트 작성 → 실패 확인 → 구현 → 통과 → 커밋 (순서 엄수)
→ 계획 문서 체크박스 갱신을 같은 커밋에 포함
→ 막히면 추측하지 말고 중단 후 질문
→ 게이트를 실제 명령으로 검증하고 보고한 뒤 정지 (PR 생성은 지시가 있을 때만)
```

여기에 세션마다 **'이 세션 특이사항'** 한 블록을 붙여 변수를 흡수했다.

* M2·M3 — "실데이터 다운로드가 막히면 중단 말고 표본으로 진행하되, **실패 사실을 기록에 남길 것**"
* M5 — "리포트 구조는 프론트와의 계약이니 키 이름을 임의로 바꾸지 말 것. 불가피하면 계획 문서도 같이 고치고 사유 보고"
* M6 — "기획 문구 3건 수신 여부를 **시작할 때 물을 것**. 미수신이면 임시 문구로 구현하고 그 사실을 보고에 남김"

| 성격 | 실제 발언 |
| --- | --- |

메시지 초안은 사람이 그대로 디스코드로 전달했다.

## 3. AI 결과를 어떻게 검증했나

AI가 만든 것을 AI가 검사하면 자기 채점이 된다. 그걸 막기 위해 쓴 방법들이다.

### 3.1 정답지를 먼저, 기획 승인으로 잠갔다

벤치마크에 심을 취약점 목록(= 채점 기준)을 **룰 구현보다 먼저** 확정하고,
기획자의 GitHub PR 리뷰 승인을 통과 조건으로 걸었다(이슈 #16 → PR #12).
리뷰는 3라운드가 걸렸다 — 변경 요청 2회 후 승인. 1라운드 결론이 이 방식의 이유를 그대로 말한다.

> 이대로 승인하면 측정 단계에서 개발이 정답지를 고치게 되어 "기획 선확정" 원칙이 사후에 훼손됩니다.

이후 M7 프롬프트에는 "**벤치마크 목록에 룰을 맞추는 수정 금지**, 미검출은 룰 갭으로 보고"가 실행 조항으로 들어갔다.

### 3.2 완성된 제품으로 자기 자신을 진단했다

안심코드로 안심코드 저장소를 검사했다. 39초, 등급 **위험**, 발견 216건.
그리고 원인을 대조해 보니 상당수가 **자기 오탐**이었고, 숨기지 않고 [measurements.md](measurements.md)에 남겼다.

| 오탐 원인 | 내용 |
| --- | --- |
| 테스트 픽스처가 시크릿으로 잡힘 | 예외 경로가 좁아 테스트 코드의 가짜 시크릿 21건이 검출 |
| **룰 소스 자신이 룰에 걸림** | 룰 코드에 적힌 정규식 문자열이 그 룰을 발동시킴 |
| 의존성 판정 결함 | 벤치마크에서 5건으로 보이던 것이 실제 저장소에서 **74건**으로 증폭 |

셋 다 그 세션에서 고치지 않고 이슈로 넘겼다(자기 채점 방지). 다음 세션이 처리했다.

### 3.3 제품 안의 AI가 결과를 흔들지 못하게 설계하고, 그걸 실증했다

등급은 정적 분석 결과만의 함수이고 LLM 판단은 참고 표시(`review_needed`)로만 들어간다(G3).
이 설계를 **프롬프트 인젝션 4종**(한국어·영어 지시문, 역할 사칭, JSON 위장)으로 시험했다.
결과: 등급 '위험' 유지, LLM이 만든 문장 전체에서 지시문 반영 흔적 0건.
[verification/injection_payloads.md](../verification/injection_payloads.md)의 첫 소제목이 요약이다 —
**"방어의 근거는 필터가 아니라 구조다."**

### 3.4 실패도 기록에 남겼다

| 사건 | 대응 |
| --- | --- |
| 한 세션이 규약을 어기고 다른 방식으로 파일을 편집해 **변경 기록이 0건으로 남음** | PR에서 사후 복원하고, **위반 사실 자체를 로그 상단에 명시** |
| React 버전 표기가 설계 문서와 실물이 갈라짐 | 원인 세션에서 규명 후 "버전은 lock 파일에서 확인" 규약 추가 |
| 서브에이전트 4개가 사용량 한도로 동시 중단 | 한도 해제 후 개별 재개 지시 |
| Cowork 세션에 대화 기록이 없어 백업 스킬이 동작 안 함 | AI가 같은 형식으로 직접 작성하고 그 사실을 명시 |
| 원격 세션이 로컬 커밋을 보지 못한 채 PR 생성 지시를 받음 | AI가 전제 불일치를 표로 제시하고 **작업 거부 후 확인 요청** |
