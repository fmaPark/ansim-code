# 세션 대화 백업 (backup-session)

현재 세션의 트랜스크립트(JSONL)를 파싱해 사람이 읽기 좋은 마크다운으로
`<프로젝트 루트>/logs/agent/` 에 저장한다. 실제 변환은 번들 스크립트가 수행하므로
직접 트랜스크립트를 파싱하지 말고 스크립트를 실행하면 된다.

## 실행 절차

1. **세션 ID 확인** — 시스템 프롬프트의 Scratchpad 경로에 현재 세션 UUID가 들어 있다.
   예: `/private/tmp/claude-501/<프로젝트-슬러그>/<세션-UUID>/scratchpad`
   이 UUID를 `--session-id`로 넘긴다. 경로에서 UUID를 찾을 수 없으면 생략해도 된다
   (스크립트가 가장 최근에 기록된 트랜스크립트를 자동 선택한다 — 현재 세션이 계속
   기록 중이므로 사실상 항상 현재 세션이 잡힌다).

2. **대화 요약 슬러그 작성** — 지금까지의 대화를 대표하는 짧은 요약을 만든다.
   - 한글 또는 영문 단어를 하이픈(-)으로 연결, 공백·특수문자 없이 20자 내외
   - 파일 목록에서 한눈에 내용을 알 수 있게 구체적으로 (예: `로그인-API-버그수정`,
     `TDD-문서-검토`, `세션백업-스킬-생성`)
   - 나쁜 예: `작업`, `대화`, `backup` — 무엇을 했는지 드러나지 않는다

3. **스크립트 실행**

   ```bash
   python3 "<이 스킬 디렉토리>/scripts/export_session.py" \
     --summary "<요약-슬러그>" \
     --session-id "<세션-UUID>"
   ```

   스크립트가 날짜와 순번({num})을 자동 계산해
   `logs/agent/YYYY-MM-DD-{num}-{요약}.md` 로 저장하고 결과 경로를 출력한다.
   같은 날짜에 이미 백업이 있으면 순번이 1씩 증가하므로 덮어쓸 걱정은 없다.

4. **결과 보고** — 저장된 파일 경로, 사용자 턴 수, 변경 파일 개수를 사용자에게 알린다.
   백업 파일을 열어 다시 요약할 필요는 없다.

## 옵션

| 옵션 | 용도 |
|------|------|
| `--project-dir <path>` | 프로젝트 루트 지정 (기본: git 루트, 없으면 cwd) |
| `--output-dir <path>` | 저장 위치 변경 (기본: `<프로젝트>/logs/agent`) |
| `--include-thinking` | Claude 내부 사고 과정 블록도 포함 (기본 제외) |

## 출력 형식 (스크립트가 자동 생성)

- **헤더 테이블**: 백업 일시, 세션 ID, 프로젝트, 대화 시작/종료 시각, 사용자 턴 수
- **📁 업데이트된 파일**: Write/Edit/NotebookEdit로 변경된 파일의 경로·작업·횟수 테이블
- **💬 대화 내용**: `👤 사용자` / `🤖 Claude` 헤더로 주체를 구분한 시간순 전문.
  Claude 턴에는 실행한 도구 호출이 한 줄씩 요약되어 붙는다.
  도구 실행 결과(출력)와 시스템 주입 텍스트는 가독성을 위해 제외된다.

## 주의

- 세션 도중 여러 번 호출해도 된다 — 호출 시점까지의 내용이 새 순번으로 저장된다.
- 트랜스크립트를 찾지 못하면 스크립트가 원인을 출력한다. 이때는 에러 메시지의 경로를
  확인해 `--project-dir`를 명시적으로 지정해 본다.
- Bash로 생성된 파일(리다이렉션 등)은 파일 목록에 잡히지 않는다. 대화 중 그런 파일이
  중요했다면 결과 보고 시 한 줄 언급해 준다.
